# 결정 인터뷰 질문 목록

## 7. 범위

자료(기획서 · 메모)에 나오는 기능을 **전부** 모아 표로 보이고, 각각 이번 단계 / 선택 / 로드맵 / 하지 않음으로 나눈다.

추천 기준:
- ⓐ 자료가 "이번 단계까지"라고 적은 것 → 이번 단계
- ⓑ 핵심 사용 흐름(시연 · 첫 출시에서 보여야 할 흐름) → 이번 단계
- ⓒ 각 파트가 맡을 일이 있어야 한다 — 한 파트가 비면 그 파트 몫의 기능을 다시 본다
- ⓓ 실제로 시간이 흐르거나 데이터가 쌓여야 하는 것(실증 · 보정 · 장기 지표) → 로드맵
- ⓔ 자료가 "선택"이라 한 것 → 선택

답이 정하는 것: PRD 범위 표, 기능 목록(F). 범위 표를 받쳐 주는 기능(계정 · 설정 · 측정 등)도 F로 만든다.

## 13. 핵심 흐름별 세부

범위의 핵심 흐름마다 묻는다. 자료에 이름만 있고 정의가 없는 개념(상태 이름 · 등급 · 카드 구성)을 찾아 정의를 제안한다.

| 질문 | 추천 기준 |
|---|---|
| 입력 · 판정 규칙 · 출력 | 판정은 규칙이 하고, 같은 입력이면 같은 결과가 나와야 설명할 수 있다 |
| 예외 — 못 찾음 · 모름 · 답하지 않음 · 오프라인 · 실패 | "못 찾음"을 "없음"으로 판정하지 않는다. 예외마다 상태와 안내를 정한다 |
| 결과물의 구성(카드 · 리포트 · 알림의 항목) | 자료에 있는 항목을 그대로 가져오고, 더하는 항목은 이유와 함께 제안 |
| 반복 · 재방문 흐름(재점검 · 재시도 · 갱신) | 같은 엔진을 다시 쓰고 판정 로직을 따로 만들지 않는다. 시간 경과가 필요하면 "언제든 시작 + 알림"으로 시연 장치를 피한다 |
| 답 수정 | 입력은 언제든 고치고 결과가 바로 다시 계산되게(시연 전용 모드 대신 일반 기능) |

## 15. 비기능

범주마다 **해당 / 해당 없음 / U**로 짚는다. 빠뜨린 범주가 없게 하는 것이 목적이다.

보안 · 인증 · 성능 · 가용성 · 운영(로그 · 모니터링 · 백업) · 배포 환경 · 비용 · 법 · 규제 · 접근성 · 다국어 · 오프라인 · 기기 · 브라우저.

추천 기준: 자료에 목표치가 있으면 그것을 목표로, 없으면 값을 지어내지 말고 "측정해서 공개" 또는 U.

| AI가 실패하거나 확신이 낮을 때 | 규칙 부분은 계속 돌게, 확신 낮음은 "확인 필요 · 보류"로 |
| 점수 표시 | 정답 확률이 아님을 표기 |
| 평가 | 평가셋은 학습 데이터와 단위(가구 · 사용자 · 문서) 기준으로 분리, 지표 · 목표 · 담당 |
| 외부 모델 사용 조건 | 데이터 전송 범위 · 학습 사용 여부 · 비용 |
